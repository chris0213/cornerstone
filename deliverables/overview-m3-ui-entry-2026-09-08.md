## 三、关键设计决策

1. **绕开你未提交改动的文件**。`AlertsPage.vue`、`router.ts`、`menuConfig.ts` 都在你未提交的改动列表里，本次**一律不碰**。自适应告警的规则级配置原本更适合放在告警规则编辑弹窗，为不污染你的改动，改为放在 AI 设置页 —— 这是权宜之计，等你那版改动提交后可以搬回去。
2. **两个接口都要求超管权限**，与同文件其它设置接口一致，并写入配置变更审计日志（关键字 `更新巡检AI二次研判开关`）。
3. **前端逐行保存**，改了不点保存不会提交，避免误触把一批规则切到自适应模式。
4. **后端限制在 UI 上显式暴露**：条件类型不是 `latency`/`packet_loss` 的规则，检测模式下拉直接禁用并提示「仅支持延迟与丢包规则」，避免运维反复试错。

## 四、验证结果

- `py_compile backend/src/api/settings.py` → 退出码 0
- `npx vue-tsc --noEmit` → **EXIT=0，零输出**；这是主校验门，它会对 SFC 模板做完整类型检查，本次改动引入的模板、脚本、类型全部通过
- `npx vite build` → **未能完成**，但失败原因与本次改动无关：沙箱的文件访问授权在读取 `frontend/src/features/system/SSOSettings.vue`（本次未触碰的文件）时超时被拦截，属执行环境策略限制，不是编译错误。已在 764 个模块转换之后才中断，且报错栈指向文件读取（`readFileSync`）而非语法/类型。上线前请在正常环境补跑一次 `vite build` 确认。
- 契约核对：`inspector.py:719-745` 读取的 key 与新接口写入的 key、JSON 结构完全一致（`{"enabled": bool}`，缺省视为关闭）
- 路由冲突检查：`settings.py` 内无 `/settings/{key}` 类动态路由，新静态路径不会被吞

## 五、怎么用

1. 用**超管**账号登录 → 系统设置 → AI 设置。
2. 页面顶部第一张卡片打开「巡检 AI 二次研判」（前提：下方 LLM 配置列表里至少启用一个配置）。
3. 第二张卡片挑一条**非关键**的延迟或丢包规则，切「自适应基线」→ 保存。
4. 观察 24-48 小时：自适应模式有**冷启动保护**，样本不足 10 个不告警，别误判成功能没生效。
5. 出问题就在同一页面关掉，或在运维手册「方案 A」里执行等价 SQL。

## 六、遗留项

- 自适应告警配置放在 AI 设置页不算是最佳信息架构，建议等 `AlertsPage.vue` 的改动提交后，把「检测模式 + 三个参数」并入告警规则编辑弹窗，AI 设置页只保留开关卡片。
- 巡检 AI 研判目前每次巡检固定调用一次 LLM，尚未做频次限制或异常数阈值（比如异常数为 0 时跳过）。若 token 成本敏感，这是下一个可优化点。
