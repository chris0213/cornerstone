## 📌 TL;DR（执行摘要）

- **核心矛盾不是"功能缺失"，而是"功能对目标角色不可达" + "后端过剩、前端欠曝"**：`/reports`(月报)、`/inspection`(巡检) 被 `system:read` 权限锁死，engineer/viewer 100% 不可见；AI 能力后端已完整但前端仅 ⌘K + 1 个埋藏 Tab 暴露。
- **路线四阶段递进**：M1 减法收口（权限解锁＋死功能清仓＋SoT 边界确立）→ M2 聚焦护城河（集成替代自研＋LLDP 三重叠收敛）→ M3 集成与智能（企业 IdP＋AIOps 收敛）→ M4 收敛验收（统一标签＋技术债验收线达标）。
- **立即可执行清仓约 1.6 人日**：删 `NetworkIcon.vue`/`cache.py`/`migrate.py`/空目录/`pnpm-lock.yaml`/空壳 Page，Dockerfile 增 `COPY poetry.lock` → 减 405 行、减 461MB、构建可复现。
- **五大护城河一律保留并做厚**：专线全生命周期、配置备份（多厂商+Diff+凭证加密）、IPAM 子网/IP 双层+冲突拦截、RBAC+审计+真实 IP 透传、AI 全局搜索+根因分析——均非可砍项。
- **明确 Non-goals**：不自研通用监控引擎、不重建 IdP/SSO、不堆功能、AI 不从黑盒自动执行起步、不把商品化能力当护城河。

## 1. 当前指标表现（来自数析）

- 后端 100 个 .py / 20,477 行；前端 54 个 .vue / 29,167 行。
- 分层失衡：`api : models = 13.8 : 1`（健康 ≤4:1），业务规则大量写入路由函数。
- 端点密度：共 **235 个端点**；`dashboard.py` 1,398 行 / 11 端点（127 行/端点）、`timeline.py` 212 行/端点（全仓膨胀度最高）。
- 巨石文件：9 文件 >1000 行；前端 **44.4%** 组件 >500 行。
- 技术债 P0 三项：① 数据层双源（11 页面 legacy、9 混合双源、前端 API 死代码率 21.9%、`seed.ts` 206 行假数据）；② 静默异常（111 处广泛捕获、42 处 `except:pass`；`fix` 占比 63.7% → 近 30 次 73.3%）；③ schema 迁移三头并存（alembic 仅 2 版本/24 模型，4 个野生 ALTER 脚本，`apply_migrations` 0 命中）。
- P1：构建不可复现（Dockerfile 不 `COPY poetry.lock`；双 lockfile 漂移 57 天）、测试 0.73%（vitest 基建就位仅 1 测试）、巨石文件。
- 立即可执行清仓（~1.6 人日）：删 `NetworkIcon.vue`/`cache.py`/`migrate.py`/空目录/`pnpm-lock.yaml`/空壳 Page，Dockerfile 增 `COPY poetry.lock` → -405 行、-461MB、构建可复现。

## 2. 用户反馈摘要（来自瑞思）

- **最大问题不是"功能太多"，而是"功能对目标角色不可达"**：`/reports`、`/inspection` 因权限被 `system:read` 锁死，engineer/viewer 100% 不可见，但 README 定义 viewer 需月报下载 → 必须先修权限，不能砍。
- 双视图仅 super_admin 可切换，2/3 真实用户无选择权；维护 2026 行双看板但切换器只服务演示账号。
- AI 入口非分散而是"后端过剩、前端欠曝"：仅 ⌘K + 预警页 1 个埋藏 Tab；`AIPrediction` 全项目仅 AlertsPage 引用一次。AI 是代际差异，应显性化而非删。
- 真实重叠：智能巡检（资产发现）↔ 设备台账 LLDP 发现 ↔ 设备拓扑 LLDP 链路图，三者共吃 LLDP 却分散三菜单。
- 死功能铁证：`LinkMonitor.vue` 用 Vue2 `:visible.sync` 语法失效，弹窗点了没反应 → 删页，能力并入设备台账+预警引擎。
- `system:admin` 幽灵权限：menuConfig 用其守护 6 个系统菜单，但种子表无此权限位，靠 `is_superuser` 兜底 → RBAC 细粒度在系统域实际失效。
- 护城河（绝不能砍）：专线全生命周期运营能力、配置备份（多厂商+Diff+凭证加密）、IPAM 子网/IP 双层+冲突拦截、RBAC+审计+真实 IP 透传、AI 全局搜索+根因分析。

## 3. 竞品动态（来自竞析）

- 标杆：NetBox（IPAM+DCIM SoT）、LibreNMS/Observium/Zabbix（监控/自动发现）、phpIPAM、PRTG、OpManager（Zia AIOps）、腾讯蓝鲸（监管控闭环）、监控宝（外部拨测）。
- 共识趋势：SoT 单一数据模型（只存预期状态，禁存实时状态/厂商配置）、AIOps 收敛到根因+自然语言交互、集成>自研、RBAC+SSO 是准入门槛非亮点、避免功能堆叠。
- 对基石建议（编号）：S1 配置备份改集成 Oxidized（自研 SSH 拉取器=造轮子）P0；S2 监控引擎不重造（对接 Zabbix/LibreNMS/Prometheus exporter）P0；S4 确立 SoT 边界 P0；S8 LLM 聚焦 4 护城河场景（Chat2X/RCA 助手/配置合规生成/知识库问答，检索优先+人在环+输出带引用）P0；S3 拓扑用 LLDP+SoT 派生 P1；S5 预警自适应阈值+降噪 P1；S6 权限集成企业 IdP P1；S9 统一命名标签体系 P1。
- 规避陷阱：商品化能力不当护城河、不重造通用监控引擎、SoT 边界模糊致漂移、功能堆叠非整合、AI 不从黑盒自动执行起步、SSO/RBAC 不可后置。

## 6. 利益相关者沟通要点（按受众）

### 高管视图（投资回报 / 风险）
- 战略对齐：当前痛点不是"做得少"而是"该用的用不到、该显的显不出"。路线图先收口再聚焦，避免继续堆功能稀释护城河。
- ROI：1.6 人日清仓即减 461MB / 405 行并恢复构建可复现；M2 用"集成替代自研"显著降低长期维护成本（配置备份、监控引擎不再重复造轮子）。
- 关键风险（需决策）：M2/M3 引入外部依赖（Oxidized、Zabbix、企业 IdP）涉及跨团队/跨厂商协作排期；AI 四大场景需明确"人在环"边界以防幻觉引发的运营事故。
- 护城河承诺：五大护城河不动，并随阶段做厚，确保差异化竞争力。

### 工程视图（技术债清理节奏）
- 节奏：M1 先止血（权限+死功能+清仓+SoT 边界），M4 末验收，技术债清理贯穿全程但硬指标在 M4 锁定。
- 验收线（务必度量）：fix 占比 73.3%→≤40%、`useAppStore` 页面 11→0、前端 API 死代码率 21.9%→≤5%、`except:pass` 42 处→≤5%、>1000 行文件 9→≤3、测试覆盖 0.73%→≥10%。

### 设计 / 产品视图（信息架构收敛与 AI 显性化）

- 命名与标签：M4 落地统一命名标签体系（S9），为跨模块检索与 AI 问答提供一致语义基底。
- 用户可达性优先：所有"不可见"问题优先归类为权限/IA 缺陷，不轻易走"砍功能"路径。

**待确认**
- 当前项目无任何使用埋点，"低使用率"判断均为代码考古推断；建议 M1 先加最小埋点（路由 PV × 角色），2 周数据即可验证/推翻删减假设。在此之前只执行零风险项（A03/A04/A06）。

- 智能巡检（资产发现）是否真有生产数据？其空表可能由权限断层导致（engineer 从未可见），勿据此误判删除。
- 月报是降级还是加强，取决于 2 位 IT 负责人确认（是否每月必呈报 CIO）。

**假设**
- 团队具备对接 Oxidized/Zabbix/企业 IdP 的运维通道；外部依赖 SLA 在可接受范围。
- 现有 5 大护城河功能为事实需求，路线图默认保留。

**Non-goals（明确不做什么）**
- 不自研通用监控引擎（对接成熟引擎）。
- 不重建 IdP / SSO（集成企业现有 IdP）。
- 不堆功能 / 不做功能堆叠式扩展（以整合替代叠加）。
- 不把商品化能力（基础 IPAM、基础监控、自动发现、配置拉取）当护城河。
- 不重造 SSH 配置拉取器（用 Oxidized 集成）。
- AI 不从"黑盒自动执行"起步（检索优先 + 人在环 + 输出带引用）。
- 不砍五大护城河；不删 `/reports`、`/inspection`（其问题是权限不可达，非功能冗余）。
- 不做 SoT 边界模糊的"中间态"（要么预期状态、要么外部实时，禁止漂移）。
